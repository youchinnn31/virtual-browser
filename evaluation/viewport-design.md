**ビューポートレンダリング評価の設計**

作業ブランチは `feat/viewport-evaluation`。LCP評価の実装を引き継ぎ、準備アクセス1回の後、ビューポートだけを各サイトn回測定する。比較条件を揃えるため、準備アクセスは本計測と分けて中央値から除外する。

**評価単位と回数**

| 単位                  | 内容                                                                      |
| --------------------- | ------------------------------------------------------------------------- |
| 評価全体（runId）     | 指定した全サイト・全通信条件を実行する単位。DB1個と全体のCSV2個を生成する |
| 1評価（evaluationId） | 1サイト・1通信条件について準備1回＋本計測n回を実行する                    |
| 1測定（trialId）      | 対象サイトへアクセスし、ビューポート画像1枚を生成・転送・描画する         |

nは正の整数として指定でき、既定値は5回とする。入力欄は「再アクセス回数」から「計測回数」へ変更する。初期URLは現在の30サイトを引き継ぐ。

直前の比較条件に関する方針に合わせ、集計対象外の準備アクセスを1回実行する。n=5ならアクセスは合計6回で、準備後の5回を集計する。LCP評価の「初回1回＋再アクセスn回」と同じ回数・ブラウザ状態の扱いとする。

**1回の計測の流れ**

1. サーバが試行IDと区分・測定番号（準備は0、本計測は1〜n）を通知する。
2. クライアントが計測開始時刻t0を `performance.now()` で取得し、測定開始要求を送る。
3. サーバが `await page.goto(url, { waitUntil: "networkidle2" })` で待機する。
4. 上記の待機が正常に完了した後、ページを先頭へスクロールしてビューポート全体をWebPで撮影する。撮影前の追加待機は設けない。
5. 現在と同じ64,000バイトの上限・幅半減の処理で画像を加工し、WebSocketで送る。
6. クライアントが画像を読み込み、Canvasの `(0, 0)` に `drawImage()` する。
7. `drawImage()` 直後の時刻t1を取得し、結果と描画完了をサーバへ通知する。
8. サーバが結果をDBへ保存した後、次の測定へ進む。

各回で `page.goto()` を実行し、毎回networkidle2の完了を待つ。LCP候補の観測・保存・DOM照合・候補画像の生成・候補描画完了通知は使用しない。

**計測値の定義**

```text
ビューポート画像表示時間（ms） = t1 − t0
t0 = クライアント端末が測定開始要求を送信する直前
t1 = ビューポート画像のdrawImage直後
```

対象サイトへのアクセス、networkidle2の待機、撮影、加工、端末への転送、画像読み込み、Canvas描画までを含む。networkidle2は撮影開始の条件であり、計測開始時刻にはしない。端末内の時刻差を使用し、サーバとの時計同期は不要である。

1回に描画する画像は1枚のため、最初の画像描画とビューポート描画完了は同じ時点になる。評価値は `viewport_ms` に一本化し、標準LCPやサーバ側の候補LCP時刻としては扱わない。画像が実際に画面へ提示されたフレームの確認は追加せず、従来と同じdrawImage直後を終了時刻とする。

**画面・通信・ブラウザ状態**

- 計測画面のHTML/CSSと、WebSocket接続時にCSS寸法を端末DPRで割る寸法計算を維持する。独自の高さ補正、CSS幅の追加保存、リサイズ時の中断は追加しない。
- 評価設定・結果は現在の固定パネルで表示する。計測画面の幅やCanvasの位置へ影響させない。
- 端末UA、サーバのDPR 1、画像加工、WebSocketの画像表現・圧縮設定を現在と揃える。
- Charlesは別PCで設定する。通信条件ごとの手動確認を維持し、アプリ内の通信制限は追加しない。
- サイト・通信条件ごとに独立したブラウザコンテキストとPageを作る。同じ評価の準備1回＋本計測n回は同じPageで実行し、Cookieやキャッシュなどの状態を維持する。

新しいコンテキストで準備アクセスを実行し、同じPageで本計測n回を行う。集計対象は準備後のアクセスとし、LCP評価と準備回数・Cookieやキャッシュの保持範囲を揃える。

**集計・失敗時の扱い**

- 各サイト・通信条件の準備を除いたn回の `viewport_ms` の中央値を正式な評価結果とする。偶数件は中央2値の平均とする。
- 指定n回、有効な計測数、中央値、評価状態を保存する。欠測を0msに置き換えず、n件すべてが有効でなければ正式な中央値はNULLとする。
- 失敗は1試行として記録し、自動リトライでn回を増やさない。
- タイムアウト等でPageを閉じた場合は、現在の評価方式と同様、残りをスキップとして記録する。途中でPageを作り直してキャッシュ条件を変えず、次のサイト・通信条件へ進む。
- ナビゲーションはPuppeteer既定のタイムアウトを使う。別に1測定全体の上限を現在と同じ既定60秒とし、変更可能にする。Charlesの設定確認待ちは上限の対象外とする。
- 端末のバックグラウンド化・切断・手動停止は実行全体の中断とし、保存済みの値と中断状態を書き出す。

**保存先と出力**

標準の保存先は、サーバPC上のプロジェクトにある `evaluation/results/viewport/<runId>/` とする。起動フォルダに依存しない保存先の解決、環境変数による変更、絶対パスの画面表示、保存成功・失敗のログを引き継ぐ。既存のLCP評価結果は書き換えない。

| ファイル            | 内容                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| `evaluation.sqlite` | 評価全体の設定・端末情報・方式・各サイトの集計・全測定の結果                                                  |
| `measurements.csv`  | サイト、通信条件、方式、準備/本計測の区分・測定番号、最終URL、状態、viewport_ms、画像枚数、エラー等の生データ |
| `summary.csv`       | サイト、通信条件、方式、指定n、有効数、median_viewport_ms、評価状態                                           |

DBとCSVに方式 `viewport` を記録し、LCP評価と識別できるようにする。LCP候補テーブルやLCP専用の集計項目はビューポート評価では使用しない。新規実行用のスキーマ・CSVとし、過去のDBの移行は行わない。

準備・各測定後にDBへ保存し、サイト・通信条件の評価終了時と実行全体の終了・中断時にCSVを更新する。CSVのBOM・エスケープ・一時ファイルからの更新、終了後のダウンロードを引き継ぐ。

**実装箇所**

通常用サーバを呼び出す構造は追加せず、評価用コードをこのブランチでビューポート方式へ変更する。

| ファイル                           | 変更内容                                                                                |
| ---------------------------------- | --------------------------------------------------------------------------------------- |
| `src/evaluation/index.ts`          | n回のループ、networkidle2後のビューポート画像1枚の生成、LCP候補処理の除去、保存先の分離 |
| `src/evaluation/protocol.ts`       | 計測回数measurementCount、測定番号、ビューポート専用の結果・通知へ変更                  |
| `src/evaluation/store.ts`          | n回の測定とビューポート方式を保存する新規DBスキーマへ変更                               |
| `src/evaluation/report.ts`         | n回のviewport_msを集計し、専用のCSVを出力                                               |
| `src/client/evaluation/index.ts`   | 1枚のビューポート画像の描画・計測・完了通知へ変更                                       |
| `src/client/evaluation/index.html` | 計測回数・結果列・説明をビューポート評価向けに変更                                      |
| `evaluation/README.md`、評価テスト | 操作・保存先の説明と検証を更新                                                          |

**確認内容**

1. n=5なら各サイト・通信条件で準備を含め6回のアクセスと6枚のビューポート画像になり、集計は準備を除いた5件を対象にする。
2. networkidle2の待機が終わる前には撮影・画像送信を行わない。
3. サーバの処理時間ではなく、端末の要求送信直前からdrawImage直後までを記録する。
4. 描画完了・保存前に次の試行を開始しない。古い試行IDの通知は混在させない。
5. 通常用画面とDPR 1・2・3のCanvas寸法・位置が一致する。
6. n件が揃わない場合のNULL、タイムアウト・中断、保存先、CSVとDBへの保存を確認する。
