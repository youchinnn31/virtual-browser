# 2回目以降の表示時間の測定

リポジトリのルートで実行します。Node.jsとPuppeteerのChromeが必要です。
ポート3000を使用するため、通常の代理サーバーは停止しておいてください。

```sh
npm install
npm run evaluate:repeat
```

`evaluation/urls.json` のURLを、128・200・300・1024 kbpsで順番にクロールします。
URLと通信速度の組み合わせごとに専用DBと代理サーバーを起動し、次の順番でアクセスします。

1. 初回：LCP候補とクライアントの表示時間を収集します。中央値には含めません。
2. 2〜6回目：同じDBを保持して5回測定し、その5値の中央値を求めます。

DBのキーには指定したURLを使います。リダイレクトや履歴APIで遷移後URLが変わっても、同じ指定URLの候補と初回値を再利用します。遷移後URLはExcelに別途記録します。

測る値は、既存クライアントが送信する「URL送信から最初の画像をCanvasへ描画するまでの時間」です。
ブラウザ標準のLCPとは異なります。最初の画像描画後も、全画像の描画とサーバーの処理完了を待ってから次へ進みます。
既存の `evaluation/evaluation.mjs`、クライアント、通常のDBは変更・使用しません。

## 出力

`evaluation/results/lcp-<時刻>.xlsx` に以下の3シートを出力します。

- `中央値`：2〜6回目の5値、中央値、初回値、収集候補数、成功・失敗状態、DBパス。
- `測定値`：アクセスごとの値、LCP部分画像数、リダイレクト後URL。
- `測定条件`：キャッシュ・通信・測定方法の条件。

URL・通信速度ごとのDBはExcelと同じ場所の `<出力名>.xlsx.data/` に残します。
途中で失敗した条件は再試行せず、取得できた値と失敗理由を出力して次の条件へ進みます。
5回成功しなかった条件には中央値を出しません。失敗があれば終了コードは1になります。
同じ出力名を再利用するとエラーにし、前回の測定DBの混入を防ぎます。

## 対象・通信速度の指定

URLファイルはHTTP(S) URLのJSON配列です。指定パスは実行ディレクトリからの相対パスです。

```sh
npm run evaluate:repeat -- --urls evaluation/urls.json --speeds 128 --output evaluation/results/repeat.xlsx
```

`--timeout 120000` は各アクセス・起動待ちのタイムアウト（ms）です。
代理サーバー内の既存 `page.goto()` のタイムアウトは変更していません。

## 評価条件

代理サーバーとクライアントでHTTPキャッシュを無効にし、Service Workerをバイパスします。
DNSキャッシュ、接続の再利用、対象サイト・CDN側のキャッシュは消去しません。
通信制限は従来の評価と同様にクライアント側へ適用し、代理サーバーから対象サイトへの通信は制限しません。

先行描画は初回の表示時間が収集済みなら、その時間にかかわらず2回目以降に実行されます。
保存済みXPathの要素が見つからない場合も測定し、LCP部分画像数が0として記録されます。
初回のLCP候補保存は既存の `access_num === 1` 条件を維持しており、アクセス数加算後の候補は保存されません。

`LCP_EVALUATION=1` はクロール専用です。通常のブラウザ利用時は設定しないでください。
クロールはクライアントの画像処理に渡す前に、評価用の完了通知を受け取ります。

## 検証

```sh
npm run build
node --test evaluation/repeat.test.mjs
```

ローカルのキャッシュ可能なページへ初回＋5回アクセスし、キャッシュ無効、先行描画、DB保持、Excelと中央値を確認します。
