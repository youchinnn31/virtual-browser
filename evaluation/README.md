# モバイル端末でのビューポート評価

`feat/viewport-evaluation` は、各サイト・通信条件で準備アクセス1回の後、ビューポートレンダリングをn回計測するブランチです。準備アクセスは中央値から除外します。
通常用サーバを呼び出さず、独立した `src/evaluation/index.ts` が画像処理と評価進行を行います。

## 起動

依存パッケージとPuppeteerのChromeがインストールされた環境で、プロジェクトルートから実行します。

```sh
npm run evaluation
```

ビルドと起動を分ける場合は以下です。

```sh
npm run evaluation:build
npm run evaluation:start
```

モバイル端末で `http://<評価サーバPCのIPアドレス>:3001/` を開きます。実機ブラウザ内のJavaScriptが評価を自動進行します。Puppeteerはサーバ側で対象サイトを取得・画像化するために使用します。

| 変数                        | 初期値                        | 内容                             |
| --------------------------- | ----------------------------- | -------------------------------- |
| `EVALUATION_PORT`           | `3001`                        | 評価サーバのポート               |
| `EVALUATION_RESULTS_DIR`    | `evaluation/results/viewport` | 保存先のルート                   |
| `PUPPETEER_EXECUTABLE_PATH` | PuppeteerのChrome             | Chrome実行ファイルを指定する場合 |

評価用ビルド先は `dist/evaluation/` です。通常用の `npm run build` は既存どおりdist全体を削除するため、その後は評価用を再ビルドしてください。

## 実行手順

1. 別PC上のCharlesを経由するようにモバイル端末の通信環境を設定します。
2. 初期値の30サイトを必要に応じて編集し、通信条件名、計測回数n、1アクセス全体の上限を入力します。既定はn=5、上限60秒です。
3. 「評価を開始」を押します。
4. Charlesを指定の条件に設定し、「設定済み・評価を進める」を押します。
5. 各サイトで準備アクセス1回と本計測n回を自動実行します。次の通信条件では再び手動確認を待ちます。
6. 終了後、全体のCSVとDBをダウンロードできます。サーバPCにも自動保存します。

設定と結果は、計測画面の配置に影響しない固定パネルで表示します。途中で進捗や中断ボタンを使う場合は、計測画面の「送信」でパネルを開きます。「計測画面を表示」で閉じられます。

アプリからCharlesを操作せず、Puppeteer/CDPによる通信制限も追加しません。モバイルと評価サーバ間のWebSocket通信にも設定した制限がかかることを実機で確認してください。評価サーバから対象サイトへの取得通信は別経路です。

ページを前面に表示し、画面幅と端末の向きを固定してください。バックグラウンド化、切断、「中断」で評価全体を中断し、保存済みの結果を書き出します。自動再接続は行いますが、評価の自動再開・リトライは行いません。従来と同様、リサイズの監視・自動中断は追加しません。

## 計測の流れと集計

- 評価全体（runId）: 全URL・全通信条件の一括実行。DBは1個です。
- 1評価（evaluationId）: 1サイト・1通信条件の準備1回＋本計測n回。
- 1アクセス（trialId）: 準備または個々の本計測。

各アクセスで `page.goto(url, { waitUntil: "networkidle2" })` を実行し、正常に完了した後、ページ先頭へスクロールしてビューポート全体を撮影します。撮影前の追加待機はありません。WebP画像を最大64,000バイトまで幅半減で加工し、画像1枚をWebSocketで送信します。LCP候補の観測・保存・DOM照合は行いません。

クライアントは画像のload時にCanvasへ描画し、次の時間を測定します。

```text
ビューポート画像表示時間 = drawImage直後 − 測定開始要求の送信直前
```

対象サイトへのアクセス、networkidle2待機、撮影、加工、転送、画像読み込み、Canvas描画までを含む、クライアント端末内の時間差です。networkidle2は撮影開始条件であり、計測開始時刻にはしません。描画完了通知とDB保存が終わるまで次のアクセスを開始しません。

準備も本計測と同じ処理でビューポート画像を1枚表示し、参考値として保存します。準備後の本計測n件だけを中央値に使います。n=5ならアクセス・画像は合計6回・6枚、集計対象は5件です。
nが偶数なら中央2値の平均を使います。n件すべてが有効でなければ正式な中央値はNULLとし、成功数と失敗理由を残します。

準備に失敗した場合は本計測をスキップします。タイムアウト等でPageが終了した場合も、その評価の残りをスキップして次の評価へ進みます。途中でPageを作り直してブラウザ状態を変える処理は行いません。ナビゲーションの上限はPuppeteer既定のまま、別に1アクセス全体の上限（既定60秒）をサーバ・クライアントで監視します。Charlesの設定確認待ちは上限の対象外です。

## 画面とブラウザ状態

従来の見出し・URL欄・CanvasのHTML/CSSを使い、meta viewportを追加しません。WebSocket接続時に従来と同じ式で寸法を確定します。

```text
幅 = Math.trunc(CanvasのCSS幅 / 端末DPR)
高さ = Math.trunc((innerHeight − Canvasの上端位置) / 端末DPR)
```

独自の高さ補正や最小値、CSS幅の追加保存はありません。実行開始やリサイズ時には再計算しません。サーバのDPRは1です。

サイト・通信条件ごとに新しいブラウザコンテキストを作成し、準備と本計測n回では同じPageを使用してCookie・キャッシュなどの状態を維持します。端末UA・寸法・DPR、ビルド元コミット、ブラウザ/Nodeバージョン、方式、準備回数もDBに記録します。

## 出力

標準保存先は、サーバPCのプロジェクト内の以下の場所です。起動フォルダには依存しません。

```text
evaluation/results/viewport/<runId>/
  evaluation.sqlite
  measurements.csv
  summary.csv
```

- `evaluation.sqlite`: 方式viewport、設定・端末情報・各アクセス・集計。LCP候補テーブルはありません。
- `measurements.csv`: 準備（phase=warmup、measurement_index=0）と本計測（phase=measurement、measurement_index=1〜n）の生データ。viewport_msが計測時間です。
- `summary.csv`: サイト・通信条件ごとの指定n、成功数、median_viewport_ms、評価状態。

DBとCSVに方式viewportを記録します。LCP評価の過去のDBやCSVは書き換えません。

各アクセス後にDBへ保存し、各評価終了時と実行全体の終了・中断時にCSVを更新します。最初の評価が終わるまではDBだけが存在します。CSVはExcelで開けるUTF-8 BOM付きで、NULLは空欄です。

設定・進捗パネルに「サーバPCの保存先」として絶対パスを表示します。起動・保存完了・保存失敗のログにも保存先を表示します。実行中のダウンロードは完了を待つよう案内します。
`EVALUATION_RESULTS_DIR`を指定した場合はその場所を使用し、相対パスの場合は起動フォルダを基準とします。

## 確認

```sh
npm run evaluation:build
npm run evaluation:test
npm run lint:tsc
```

テストはローカルHTTPページとChromiumを使用し、networkidle2待機、準備を除く中央値、描画通知、ブラウザ状態の分離、エラー・中断・保存を確認します。DPR 1・2・3で通常用画面とCanvasの寸法・位置を比較します。
実機Safari/ChromeとCharlesの通信制限は実機で別途確認してください。
