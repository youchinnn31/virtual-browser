# モバイル端末でのLCP画像評価

通常用の `src/server/index.ts` は使わず、独立した `src/evaluation/index.ts` を起動します。
画像処理と評価進行は評価用の `index.ts` に実装しています。

## 起動

依存パッケージとPuppeteerのChromeがインストールされた環境で、プロジェクトルートから実行します。

```sh
npm run evaluation
```

ビルドと起動を分ける場合は以下です。

```sh
npm run evaluation:build
npm run evaluation:start
```

実機モバイル端末で `http://<評価サーバPCのIPアドレス>:3001/` を開きます。
端末のブラウザ内のJavaScriptで自動評価します。クライアント操作用のPuppeteerやWebDriverは必要ありません。
Puppeteerはサーバ側のページ取得・画像化に使用します。

環境変数で設定を変更できます。

| 変数                        | 初期値               | 内容                             |
| --------------------------- | -------------------- | -------------------------------- |
| `EVALUATION_PORT`           | `3001`               | 評価用サーバのポート             |
| `EVALUATION_RESULTS_DIR`    | `evaluation/results` | 評価全体の保存先                 |
| `PUPPETEER_EXECUTABLE_PATH` | PuppeteerのChrome    | Chrome実行ファイルを指定する場合 |

評価用のビルド先は `dist/evaluation/` です。既存の通常用ビルド・起動コマンドはそのまま使用できます。
通常用の `npm run build` は既存仕様どおり `dist/` 全体を掃除するため、通常用ビルドの後は評価用を再ビルドしてください。

## 実行手順

1. 別PC上のCharlesを経由するよう、モバイル端末の通信環境を設定します。
2. 評価ページに複数URL、通信条件名、再アクセス回数 `n`、1アクセス全体の上限を入力します。
3. 「評価を開始」を押します。
4. 指定された通信条件をCharles側で設定し、「設定済み・評価を進める」を押します。
5. 以降は各サイトの初回1回と再アクセスn回を自動実行します。次の通信条件では再び設定確認を待ちます。
6. 終了後、評価全体のCSVとDBをダウンロードします。

通信条件名には速度・遅延など、Charlesで実際に設定した条件を記載してください。
アプリはCharlesを操作せず、Puppeteer/CDPによる通信制限も追加しません。
制限対象はモバイルと評価サーバ間です。画像はWebSocketで転送するため、実機でその通信にも制限がかかることを事前に確認してください。
評価サーバから対象サイトへの取得通信は別経路です。

ページは前面に表示し、画面幅を固定してください。
バックグラウンドへの移動、画面幅の変更、切断、「中断」では評価全体を中断し、保存済みの結果を書き出します。
接続復帰後の自動再開・自動リトライは行いません。

## 評価単位と表示

- 評価全体 (`runId`): 全URL・全通信条件を一括実行する単位。DBは1つです。
- 1評価 (`evaluationId`): 1サイト・1通信条件の初回1回＋再アクセスn回。
- 1アクセス (`trialId`): 初回または個々の再アクセス。

初回は `lcp.js` のPerformanceObserverで候補を取得し、`networkidle2` 到達時に候補を確定します。
既に待機中のObserverレコードを回収し、候補の保存完了を待ちます。追加の観測待ち時間は設けません。
リダイレクト前の文書の候補は採用せず、最終URLの候補を保存します。
初回の表示はビューポート画像1枚です。

再アクセスでは、初回の保存候補をLCP時刻の降順で取得します。
XPathで要素を検索し、描画領域が得られた候補をすべて画像化します。
過去の要素が今回もLCPであるかという再判定はしません。
4秒の条件分岐はありません。全LCP候補の描画完了をクライアントから確認した後、ビューポート全体画像を生成・送信して表示します。
通常用サーバはLCP画像の送信後にビューポート処理を始めますが、評価用では実際の描画完了通知まで待ちます。
候補がない場合、全候補のDOMがない場合、描画領域がない場合は計測失敗です。

候補順序・WebP・画像サイズの上限64,000バイト・半分ずつ縮小する処理・WebSocket圧縮条件は既存方式を踏襲します。
端末のCanvasのCSS幅・高さをサーバのビューポートに使い、サーバのDPRは既存同様1です。
端末のUAとDPRもDBに記録します。
1評価の内部ではサーバ側のブラウザ状態を保持し、次の評価では独立したブラウザコンテキストに切り替えます。

## 計測と処理の終了

クライアント端末で次の時間差を測定します。

```text
LCP初回画像描画時間 = 最初のLCP画像のdrawImage直後 − 画像取得リクエスト送信直前
ビューポート描画完了時間 = ビューポート画像のdrawImage直後 − 同じリクエスト送信直前
```

この値は標準LCPではなく、クライアントでのLCP画像初回描画時間です。
送信順と画像の読み込み・描画完了順が一致することは前提にしていません。
最初に描画できた画像の番号も保存します。

両方の時間は同じアクセス開始時刻を基準とします。ビューポート完了時間は補完処理だけの所要時間ではありません。
クライアントはLCP画像の送信完了通知と、その枚数すべての描画完了を確認して、LCP描画完了を通知します。
サーバはその通知を受けてからビューポートの撮影・圧縮・送信を開始します。
ビューポート画像を描画しても確定済みのLCP初回画像描画時間は更新しません。
ビューポート描画完了と結果保存が終わるまで、次のアクセスは開始しません。
初回アクセスはビューポート1枚のみで、その表示時間は参考値です。
古い試行IDの画像や通知は次の試行に混ぜません。

サーバの `page.goto` はPuppeteer既定のナビゲーション上限（使用中のバージョンでは30秒）です。
別に、試行の開始準備完了通知からビューポート描画完了の受領まで、初期値60秒の上限を設けます。
クライアントも同じ設定値で、計測開始からビューポート描画までを監視します。Charlesの設定確認待ちは上限の対象外です。
初回画像が表示されても残りの画像が終了しなければ、全体上限の対象です。

最終評価値は、再アクセスn回のLCP初回画像描画時間とビューポート描画完了時間、それぞれの中央値です。
初回アクセスは参考値としてのみ保存し、中央値には含めません。
nが偶数なら中央2値の平均です。指標ごとにn件が揃わなければ、その正式な中央値はNULLです。
LCP値は全候補の描画完了を確認したアクセスを有効とし、ビューポート値は補完描画完了を確認したアクセスを有効とします。
LCP描画完了後にビューポート処理だけが失敗しても、確認済みのLCP計測値を破棄しません。
全候補描画を確認できなかった場合も途中の生データは残しますが、そのLCP値は正式な中央値に含めません。
初回が失敗した場合、残りの再アクセスはスキップします。
タイムアウト等でブラウザを閉じた場合も、キャッシュ条件を変えて続行せず、その評価の残りをスキップして次の評価に進みます。

## 出力

```text
evaluation/results/<runId>/
  evaluation.sqlite
  measurements.csv
  summary.csv
```

- `evaluation.sqlite`: 設定・端末情報・ビルド元コミット・ブラウザバージョン・候補・各アクセスの結果。
- `measurements.csv`: 初回と各再アクセスの生データ。`first_image_ms` が最初の画像描画時間、`lcp_images_ms` が全LCP候補描画完了時間、`viewport_ms` がビューポート完了時間です。初回の `first_image_ms` は参考値です。
- `summary.csv`: 全サイト・通信条件を並べた、LCP中央値 (`median_client_lcp_image_ms`) とビューポート中央値 (`median_viewport_ms`)、それぞれの成功数・指定n回・評価状態。

画面のLCP枚数は候補画像の送信数、総枚数は候補画像とビューポート画像を合わせた送信数です。
互換用の `all_images_ms` 列は `viewport_ms` と同じ値です。新規評価のDBに列を追加する方式で、以前の評価DBは書き換えません。

CSVはUTF-8 BOM付きです。NULLは空欄で、失敗を0msには変換しません。
各アクセスは都度DBに保存し、CSVは各評価終了時と評価全体の終了・中断時に書き出します。
評価中のDBダウンロードは完了を待つよう案内します。
生成物はGit管理の対象外です。

## 確認

```sh
npm run evaluation:build
npm run evaluation:test
npm run lint:tsc
```

テストはローカルのHTTPページとChromiumを使います。
PC上のモバイル表示での確認を含みますが、実機Safari/ChromeとCharlesの通信制限は実機で別途確認してください。

既存の通常サーバをそのまま起動する構造ではないため、通常側の修正は評価側へ自動反映されません。
基準となる既存処理は `src/server/index.ts` と `lcp.js` です。
