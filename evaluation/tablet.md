# タブレット実機評価の使い方

## 起動と接続

PCでリポジトリのルートから実行します。Charlesの設定は後から追加できます。

```sh
npm install
npm run build
npm start
```

タブレットとPCを同じLANに接続し、タブレットのブラウザで次のURLを開きます。

```text
http://PCのLAN内IPアドレス:3000/evaluation
```

ポート3000への接続を許可してください。Charlesを使う場合はCharlesの待受ポート（通常8888）にも端末から接続できるようにします。評価サーバーとCharlesは同じPCで動作できます。

評価はタブレットで開いたページのJavaScriptが進めます。USB接続やPCによる実機ブラウザの遠隔操作は不要です。サーバーはタブレットのUser-AgentとCSS寸法を仮想ブラウザに設定します。仮想ブラウザのDPRは1、端末のDPRは実測値を別途保存します。

## Charlesの設定を後回しにする場合

`CHARLES_CONFIG` を指定せず起動すると、**外部速度設定モード**になります。このモードは帯域を変更しません。ページで1024kbpsを選択するだけでは、1024kbpsの回線にはなりません。

1. 画面ロックを解除し、端末の向きを固定します。キーボードを閉じてから開始してください。
2. 端末名、対象URL、測定する速度を選び、「測定開始」を押します。
3. 指定速度にCharles等を外部で設定し、「外部の速度設定を確認して続行」を押します。
4. WebSocketを再接続後、URLごとに初回収集1回＋測定5回を自動実行します。
5. 複数速度を選んだ場合は、速度が変わるごとに外部設定の確認で待機します。
6. 終了後、Excelリンクから結果を取得します。

回線を制限せず画面の動作確認をすることもできますが、その結果は指定速度での本評価には使えません。Excelには `external-unverified` と「速度は外部設定の申告値」と記録します。Charlesの設定が完了するまでは、このモードで操作・接続を確認してください。

## 計測と結果

計測するのは、端末が要求を送信する直前から、最初の受信画像を `drawImage()` でCanvasへ描画した直後までの時間です。画面への物理的な表示完了や、ブラウザ標準のLCPとは異なります。

対象サイトへのアクセスと画像化はサーバー側で行います。`networkidle2` の待機後に保存候補をLCP値の降順で画像化し、最後にビューポートを送ります。端末は同じ評価ページに留まり、画像を描画します。

- 指定URL・速度ごとに新しい仮想ブラウザのコンテキストと収集用DBを作ります。
- 初回の候補と表示時間を保存し、2〜6回目には候補を追加しません。
- HTTPキャッシュは仮想ブラウザ側で無効、Service Workerはバイパスします。端末のページはno-store、画像は新規Blobです。端末全体のキャッシュを消去する機能ではありません。
- 全画像の描画とDB保存が完了するまで、次の要求を送りません。
- 候補がない、要素が消えた、非表示等の場合も理由を記録し、ビューポートを送ります。
- 5回すべて成功した場合に全5値の中央値を出します。5回とも最初の画像がLCP部分画像であれば、先行描画評価の中央値も別列に出します。

保存先は実行ごとに分かれます。

```text
evaluation/results/tablet-<時刻>-<ID>/
  config.json
  results.db
  collected/1.db
  collected/2.db
  results.xlsx
```

Excelは「中央値」「測定値」「候補処理」「測定条件」「速度制御」の5シートです。端末情報、サーバー・Chromeのバージョン、Gitコミット、設定速度の確認・検証結果も記録します。Git情報を取得できない環境では `APP_REVISION`、Charlesのバージョンは `CHARLES_VERSION` で指定できます。

保存ルートは `TABLET_RESULTS_DIR` で変更できます。通常の `json.db` と既存のPCクロールの結果は実機評価には使用しません。

## 停止・エラー

「停止して保存」を押すと、進行中の試行を無効にして取得済みの結果を保存します。タブの非表示、向きや画面サイズの変更、通信切断でも停止します。Safari等で検出できる状態変化は実機によるため、画面ロック解除と前面表示を実験者側でも維持してください。

切断時は、保存が終わるまで待ってから表示されたExcelリンクで結果を取得してください。途中の試行を成功扱いにして再開する機能はありません。再実行は新しいDBになります。

サイトの処理失敗はその条件を終了して記録し、次の条件へ進みます。自動再試行はしません。5件揃わない条件の中央値は空欄です。タイムアウトはナビゲーション60秒、試行180秒です。

実行中は別の評価・通常の仮想ブラウザ操作を受け付けません。`Ctrl+C` / `SIGTERM` によるサーバー停止では進行中の評価を停止・保存して終了します。強制終了やPC停止では最後のExcel更新・Charles設定復元を保証できません。SQLiteには確定済み試行が残ります。

## 後日Charlesの自動制御を接続する

現時点で実環境のCharles設定は行っていません。連携処理は実装済みですが、以下を実際のバージョンで確認してから有効にしてください。

1. タブレットのWi-FiプロキシにCharlesのIP・ポートを設定する。
2. タブレットと評価サーバー間の画像用WebSocketがCharlesを通ることを確認する。仮想ブラウザ側の対象サイトへの通信は直接接続します（Chrome起動時に `--no-proxy-server` を指定）。
3. 上下同じ帯域・追加遅延0msの4プリセットを作る。
4. CharlesのWeb Interfaceを有効にし、状態取得・各プリセット有効化・制限無効化に使う操作をWeb画面から確認する。
5. `evaluation/charles.example.json` をコピーし、制御パス・HTTPメソッド・必要ならPOST本文、状態判定の正規表現を記入する。ひな形の `<...>` は未設定を表しており、そのままでは起動できません。
6. Charlesの状態応答から「有効／無効」と「現在選択中の速度」がそれぞれ一意に判別できるようにする。メニュー内の全プリセット名に一致するだけのパターンは使わないでください。
7. 設定ファイルを指定してサーバーを再起動する。

```sh
CHARLES_CONFIG=/absolute/path/charles.json npm start
```

Basic認証が必要な場合は `CHARLES_CREDENTIALS` に `ユーザー名:パスワード` を設定します。端末・Excel・実行設定には認証情報を渡しません。制御要求は指定したプロキシを通して `http://control.charles/` へ送ります。固定の制御URLを推測して実装する方式ではありません。

自動モードでは以下を行います。

1. 開始前の有効状態と選択プリセットを取得する。
2. 速度を切り替えて状態を照合し、端末のWebSocketを接続し直す。
3. 256,000バイトの非圧縮データを3回送り、端末が要求してから受信するまでの時間から実効速度を求める。中央値が設定の±20%以内の場合だけサイトの測定へ進む。
4. 切り替え・検証・終了時の復元を「速度制御」シートへ記録する。
5. 正常終了・停止・接続切断時に元のCharles設定を復元する。復元失敗時は手動確認が必要と表示する。

検証には制御メッセージ等の時間も含まれます。許容誤差（設定ファイルの `tolerance`、既定0.2）は予備実験で決定し、本測定中に調整しないでください。Charlesを迂回した未制限回線は検証不合格として本測定を開始しません。制御要求のタイムアウト既定は10秒、1回の帯域検証は120秒です。

参考：[Charles Web Interface](https://www.charlesproxy.com/documentation/using-charles/web-interface/)、[帯域制限](https://www.charlesproxy.com/documentation/proxying/throttling/)。

## 検証

```sh
npm run build
node --test --test-concurrency=1 evaluation/*.test.mjs
```

ローカルの固定ページとPCのChromeで、実機用ページの巡回・再接続・途中停止・保存、リダイレクト・非表示候補、既存PCクロール、模擬Charlesの制御・復元、未制限回線の検出を検証します。ポート3000を共有するためテストは直列で実行してください。

実物のタブレットと実際のCharlesを組み合わせた検証は別途必要です。
